# 📊 Flowchart Shapes for My MSc Thesis Workflow

## 🎯 Main principle

Different flowchart shapes communicate different meanings. Choose the shape according to what the box represents.

**Data → Processing → Analysis → Decision → Output → Planning application**

## 🔷 Common Flowchart Shapes

| Shape | Meaning | Thesis workflow use |
|---|---|---|
| 🟢 **Oval / Terminator** | Start or End | Start and End |
| 🟦 **Rectangle** | Process / activity | Preprocessing, LST retrieval, normalization, model training, SHAP analysis |
| 🟨 **Parallelogram** | Input / Output / data | Landsat data, census data, RWI, LULC maps, LST maps |
| 🔶 **Diamond** | Decision / condition | Accuracy acceptable? Best model? Additional training samples? |
| 🛢️ **Cylinder** | Database / stored data | Census database, spatial database, PostGIS, if actually used |
| 📄 **Document** | Document / report | Research report, policy document, planning recommendations |
| ➡️ **Connector / Arrow** | Flow / relationship | Connect workflow stages |
| 🔷 **Chevron** | Major stage / sequence | LULC Classification, Thermal & GeoAI Analysis, UHVI & GI Planning |
| ⬡ **Hexagon** | Preparation / special process | Optional preparation stage |
| 🟦 **Rounded Rectangle** | General process / action | Alternative process shape |
| ☁️ **Cloud** | External / cloud resource | Google Earth Engine, if explicitly shown |

## 🟦 1. Data / Inputs → Parallelogram

Use a **parallelogram** for things entering the analysis:

- 🛰️ Landsat 8 & 9 Surface Reflectance
- 🌡️ Landsat 8 & 9 Thermal Data
- 👥 Population Density
- 💰 Relative Wealth Index
- 🗺️ Administrative Boundaries

## 🟩 2. Processing → Rectangle

Use a **rectangle** for actions:

- Cloud masking
- Data preprocessing
- Spectral feature generation
- LST retrieval
- Machine learning predictive modelling
- SHAP analysis
- Normalization
- Equal weighting

## 🔶 3. Decision → Diamond

Use a **diamond** when the workflow asks a question or makes a decision.

Example:

```text
             ┌─────────────────┐
             │   LULC Model    │
             └────────┬────────┘
                      ↓
                ◇ Accuracy? ◇
                 /         \
               NO           YES
               ↓             ↓
      Additional samples   Final LULC
             │                Map
             └───────→────────┘
```

## 🟪 4. Outputs → Parallelogram

Use a **parallelogram** for products generated by the analysis:

- 🗺️ LULC Maps
- 🌡️ LST Maps
- 📊 Spectral Index Maps
- 🔥 UTFVI Maps
- 🏙️ UHVI Map
- 🌳 GI Priority Map

```text
 ↓
```


## 🌳 Important GI distinction

Use:

> **Potentially Suitable GI Intervention Types**

rather than claiming guaranteed implementation sites.

Your available data do not establish actual:

- land ownership
- land availability
- implementation cost
- engineering feasibility
- planning regulations
- community preferences
- detailed site feasibility

Therefore, GI types are **potential planning options based on observed spatial characteristics**, not confirmed implementation locations.

## 🎨 Recommended Visual Language

- 🔵 **Blue** → data / information / outputs
- 🟢 **Green** → planning / GI / environmental applications
- 🟣 **Purple** → vulnerability / composite analysis
- 🟠 **Orange** → major analytical stages
- 🔶 **Diamond** → decisions only
- ➡️ **Arrows** → workflow direction
- 🔷 **Chevron** → major methodology sections
- ⬜ **Rectangle** → processes
- 🟨 **Parallelogram** → inputs and outputs

### ⭐ Key rule

Do not change shapes randomly for decoration. The shape should help the reader understand whether something is an **input, process, decision, output, or planning application**.
